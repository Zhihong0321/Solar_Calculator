Integration API

Read users, invoices, SEDA registrations, and recorded payments. Edit selected user profile fields. These endpoints are intended for server to server integrations.

Base path: /api/integration/v1   Documentation: /api/integration/docs

This API reads the payment table, which is the app's recorded payment source. It does not read or submit submitted_payment workflow rows.

Authentication

Send the integration password in the X-Api-Password header on every API request. Ask the application owner for the password. The server uses INTEGRATION_API_PASSWORD when configured, otherwise the application default password. Keep it in a secret store and use HTTPS.

X-Api-Password: <integration-password>
Content-Type: application/json

Missing or invalid password returns 401 with {"success":false,"error":"Invalid API password"}. The documentation page is readable without the password.

Request and response conventions

Responses are JSON. Successful reads return {"success":true,"data":...}. List responses also contain limit and offset. A missing record returns 404; invalid input returns 400; server errors return 500. Database date and numeric fields keep the existing PostgreSQL JSON serialization.

ParameterApplies toMeaning
limitAll listsInteger 1–100; default 50.
offsetAll listsNon-negative integer; default 0.
:idDetail and editRecord bubble_id. Users also accept numeric database id.

List data is sorted newest first. Results are pages; request the next page with a higher offset until fewer than limit records are returned.

Users

GET/users

List user profiles. Sensitive authentication columns are omitted.

GET/users/:id

Read one user by Bubble ID or numeric ID.

PATCH/users/:id

Edit selected user profile fields. Send only the fields to change.

User responses include id, bubble_id, email, access_level, linked_agent_profile, name, contact, banker, bankin_account, user_signature, profile_picture, created_at, and updated_at. Profile values fall back to the linked agent record where appropriate.

Editable fieldRules
emailEmail format.
contactMalaysian mobile number: starts with 0, 10 or 11 digits.
name, banker, bankin_account, user_signatureString or null, at most 2000 characters.

Edits update the user record and matching agent profile in one transaction. Unknown fields, including role and access controls, are rejected.

Invoices

GET/invoices

List invoice rows. Optional exact filter: ?linked_customer=<customer-id>.

GET/invoices/:id

Read one invoice by Bubble ID.

Returns the existing invoice database fields, including invoice version fields. The list includes all versions; consumers can use is_latest to identify the current version.

SEDA registrations

GET/seda

List SEDA registration rows. Optional exact filter: ?linked_customer=<customer-id>.

GET/seda/:id

Read one registration by Bubble ID.

Returns the existing seda_registration database fields, including linked invoice IDs, applicant details, statuses, and upload references where present.

Recorded payments

GET/payments

List rows from payment. Optional filter: ?linked_invoice=<invoice-id>, including payment IDs in the invoice's linked_payment array.

GET/payments/:id

Read one recorded payment by Bubble ID.

These routes never read submitted_payment. Existing session API routes under /api/v1/submitted-payments serve the separate submission workflow.

Examples

curl -H "X-Api-Password: <integration-password>" \
  "https://YOUR-HOST/api/integration/v1/users?limit=20&offset=0"

curl -H "X-Api-Password: <integration-password>" \
  "https://YOUR-HOST/api/integration/v1/invoices/INVOICE_BUBBLE_ID"

curl -H "X-Api-Password: <integration-password>" \
  "https://YOUR-HOST/api/integration/v1/seda/SEDA_BUBBLE_ID"

curl -H "X-Api-Password: <integration-password>" \
  "https://YOUR-HOST/api/integration/v1/payments?linked_invoice=INVOICE_BUBBLE_ID"

curl -X PATCH -H "X-Api-Password: <integration-password>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Updated Name","contact":"0123456789"}' \
  "https://YOUR-HOST/api/integration/v1/users/USER_BUBBLE_ID"
{
  "success": true,
  "data": [{ "bubble_id": "...", "email": "..." }],
  "limit": 20,
  "offset": 0
}
